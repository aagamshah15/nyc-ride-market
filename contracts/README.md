# Contracts

The interfaces lanes share. Owned by L01; changed only through the integrator (docs/development-plan.md §1, §4). SPEC.md wins on anything it fixes; this folder pins what SPEC leaves open.

| File | Pins | Producer → consumers |
|---|---|---|
| this README | formats, units, nulls, mode names, `validation_summary.json` | everyone |
| [metrics.md](metrics.md) | every metric file: params, grain, output columns | L09, L10 → L11 |
| [site/pages.yaml](site/pages.yaml) | route → data files, budgets, methods anchors | L01 → L05, L11, L12–L16 |
| [site/tiles.yaml](site/tiles.yaml) | every stat tile: label, unit, change type | L01 → L05, L11 |
| [site/*.example.json](site/) | the shape of every file in `site/src/data/` | L11 → L05, L12–L16 |
| `tests/factories.py` | the clean-trip and aggregate-table schemas, as code | L06, L07 → L07–L11 tests |
| `tests/contract_check.py` | `assert_matches_contract(actual, example)` | L11, L01 tests |
| `scripts/make_mock_site_data.py` | mock site data (`make site-mock`) and the examples | L01 → site lanes |

The examples are generated: `python scripts/make_mock_site_data.py --examples` rewrites `contracts/site/*.example.json` from the mock generator, trimming every list to three items. `tests/test_contracts.py` fails if they drift. To change a site contract, change the generator, regenerate, and get the integrator's sign-off.

## 1. Site data files

### Envelope

Every file in `site/src/data/` (except `taxi_zones.geojson`) is a JSON object starting with:

| Key | Type | Meaning |
|---|---|---|
| `as_of_month` | string | latest month in the data, `"YYYY-MM"`; `"MOCK"` for mock data |
| `generated_at` | string | UTC ISO 8601, e.g. `"2026-10-24T14:00:00Z"` |
| `validated` | boolean | `true` only when `validation_summary.json` passed; deploy refuses `false` |

SPEC §9.2 shows `share_monthly.json` and `zones/index.json` as bare arrays. They are objects with a `rows` array so they can carry the envelope.

### Profile-page keys

Every page file (home, companies, zones, airports, congestion, drivers, prices) has:

- `title`: the page's headline finding, a sentence with its number, generated by `findings.py`
- `subtitles`: `{chart_id: sentence}`, one finding per chart. Chart ids are the keys of the data they draw
- `tiles`: `{tile_key: value}`, with keys from `site/tiles.yaml`
- `yoy`: the same keys as `tiles`; the change versus the same month a year earlier, typed by the tile's `yoy` kind

Page markdown renders these and never contains a number of its own (CLAUDE.md).

### Files added beyond SPEC §9.2

| File | Why |
|---|---|
| `events.json` | policy dates and labels for the dated rules on time charts, generated from `config/periods.yaml` |
| `tiles.json` | `site/tiles.yaml` as JSON, so `statTiles.js` reads labels and units from one source |

### Size

- Minified JSON (`separators=(",", ":")`) in `site/src/data/`; pretty JSON in the examples
- Per-route budget 1.5 MB (SPEC §9.2); each `zones/{zone}.json` under 50 KB
- Zone heatmaps keep only modes with at least 10% of the zone's trips in the window. With the mocks' worst case (airport zones), that keeps a zone file near 40 KB. `share_trend` adds about 220 bytes a month, so the Phase 6 back-fill (2019 on) must revisit zone-file size

## 2. Values and units

Values are raw numbers; formatting happens in `format.js` (site) and `findings.py` (sentences), both following §3.

| Quantity | Field names | Stored as | Precision |
|---|---|---|---|
| shares, rates, match rates, tip rate | `share`, `*_share`, `*_rate` | fraction 0–1 | 4 decimals |
| change in a share | `gap`, `change`, `*_change*` on shares | fraction difference (0.021 = 2.1 points) | 4 decimals |
| relative change, estimated effect | `yoy` (relative kind), `effect`, `median`, `p10`, `p90`, `change_yoy` on counts | fraction (0.031 = +3.1%) | 4 decimals |
| trips per day | `trips_per_day` | number | 1 decimal |
| trip counts | `trips`, `requests`, `matched`, `n` | integer | — |
| money | `*_fee*`, `fare_*`, `pay_*`, `cbd_fee` | US dollars | 2 decimals; per mile and per minute 3 |
| waits | `wait_*` | seconds | 0 decimals |
| months | `month` | `"YYYY-MM-01"` | — |
| weeks | `week_start` (Monday) + `iso_year`, `iso_week` | `"YYYY-MM-DD"` | — |
| hour of week | `hour_of_week` | 0–167, Sunday 00:00 = 0 (DuckDB `dayofweek`) | — |
| hour of day | `hour` | 0–23 | — |

Mode codes and display names:

| Code | Display | Kind |
|---|---|---|
| `uber` | Uber | mode |
| `lyft` | Lyft | mode |
| `other_hv` | Other ride-hail | mode |
| `yellow` | Yellow cab | mode |
| `green` | Green cab | mode |
| `ride_hail` | Ride-hail | group: uber + lyft + other_hv, unless a metric says otherwise (driver share and pay: uber + lyft) |
| `taxi` | Cabs | group: yellow + green |
| `all` | All modes | group |

## 3. Formatting rules (`format.js` and `findings.py`)

| Kind | Rule | Examples |
|---|---|---|
| count | below 1,000 exact; 1,000 and up to 3 significant figures with commas; 10 million and up as "x.y million" | 842 · 1,280 · 675,000 · 20.1 million |
| share | percent; 0 decimals at 10% and above, 1 decimal below | 84% · 3.2% |
| share change | signed percentage points, 1 decimal | +2.1 pts · −0.4 pts |
| relative change, effect | signed percent, 1 decimal | +3.1% · −7.4% |
| dollars | under $100: 2 decimals; $100 to $1 million: whole dollars with commas; above: "$x.y million" | $18.40 · $4,812 · $48.2 million |
| dollars per mile / minute / hour | 2 decimals plus unit | $2.87/mile · $1.12/min · $38.50/hour |
| seconds (waits) | minutes, 1 decimal | 4.2 min |
| month | `Jan 2025` | Aug 2026 |
| week | `week of 6 Jan 2025` | |
| hour of day | `6 am`, `12 pm`, `6 pm` | |
| hour of week | `Tue 6 pm` | |

Language (CLAUDE.md): congestion results are "estimated effects"; pay per hour is "per hour with a passenger"; taxi tips are "card-only".

## 4. Nulls

- A missing value is JSON `null`. Never `0`, never an omitted key.
- An empty list means "no rows" (for example no shared-ride data for a mode).
- Company files list unavailable metrics in `not_reported` (for taxis: `driver_share`, `wav`, `shared`); pages show "not reported for this mode".
- Zone files set `flags.thin = true` when the zone has fewer than 100 valid trips in the latest month; pages show "too few trips" instead of percentiles.
- A `yoy` value is `null` when the year-earlier value is missing or zero.
- Percentiles are `null` below n = 100 (SPEC §5); waits are `null` for taxis (no request time).

## 5. `validation_summary.json`

Written by L08 to `data/agg/validation_summary.json`; read by L11 (into `quality.json`) and L17 (deploy guard).

```json
{
  "generated_at": "2026-11-15T10:00:00Z",
  "status": "pass",
  "months_checked": ["2024-01", "2024-02", "…", "2026-08"],
  "checks": [
    {"id": "tie_out", "status": "pass", "summary": "All 31 months with indicators within ±2%; 2026-08 skipped (not yet in indicators)"},
    {"id": "quality_drift", "status": "pass", "summary": "..."},
    {"id": "cbd_list", "status": "pass", "summary": "..."},
    {"id": "schema", "status": "pass", "summary": "..."},
    {"id": "fees", "status": "pass", "summary": "..."}
  ],
  "tie_out": [{"month": "2024-01-01", "license_class": "FHV - High Volume", "pipeline_trips_per_day": 651234.5, "tlc_trips_per_day": 650100.0, "diff": 0.0017, "status": "pass"}],
  "quality": [{"month": "2024-01-01", "mode": "uber", "valid_share": 0.991, "status": "pass"}],
  "cbd": [{"zone_list": "core", "both_in_fee_share": 0.993, "neither_in_fee_share": 0.004, "status": "pass"}],
  "fees": [{"mode": "uber", "configured_fee": 1.5, "exact_share": 0.998, "other_values": [{"cbd_fee": 0.75, "trips": 120}], "status": "pass"}]
}
```

`status` is `"pass"` only when every check passes. `status` values: `pass`, `fail`, `skipped`. `diff` is relative: pipeline ÷ TLC − 1.

- `months_checked` is the full sorted list of every month checked, one `YYYY-MM` string each, not a [first, last] range; `[0]` and `[-1]` give the range. (The `"…"` above stands for the months in between.)
- `quality` rows: `status` is `fail` below 85% `valid_share` (D26). Months more than 3 points below the mode's median are listed in the check's summary and report, not failed.
- `tie_out` rows: `pipeline_trips_per_day` leaves out the records of vendors in `tie_out_exclude_vendors` (D25); the report shows how many were left out.
- `cbd` rows: only `zone_list = "core"` gates the `cbd_list` check (D21). The `wide` row carries its own pass/fail against the same 98% threshold as information, and the check's status ignores it. 2025-01, the month pricing began part-way through, is left out (D22).

## 6. Clean and aggregate schemas

The executable schemas are the builders in `tests/factories.py` (`CLEAN_TRIPS_SCHEMA`, `AGG_SCHEMAS`). They follow SPEC §4 and §5 plus these pins:

- D9: clean trips carry `cbd_pu`, `cbd_do`, `cbd_touch` (core list) and `cbd_pu_wide`, `cbd_do_wide`, `cbd_touch_wide`.
- D7, D9: `agg_week_cbd` has `month` and `zone_list`; `cbd_group ∈ {treated, control}`. Each trip appears once per `zone_list`, so sums across lists double count.
- D8: `agg_cbd_pairs`, `agg_fee_values`.
- D10, D16: `agg_zone_month_dist` has city-wide rows with `pu_zone = 0`, for each mode and for the groups `ride_hail` and `all`. Group rows exist only at `pu_zone = 0`.
- D15: `agg_od_month` has `rider_total_ex_tip`.
- Count and seconds sums are BIGINT; money and miles are DOUBLE. Sums that don't apply to a mode are NULL (for example `driver_pay` for taxis, `card_*` for ride-hail).
- `ref_indicators` keeps the CSV's column names (quoted in SQL, e.g. `"Trips Per Day"`; the month column is `"Year/Month"` in the NYC Open Data copy, D19) with numeric columns as DOUBLE, plus a parsed `month` DATE. `Percent of Trips Paid with Credit Card` is DOUBLE, a whole-number percent as published (79 = 79%), NULL for the FHV classes.
- D23: `agg_fees_month` sums every row, not only `is_valid` ones (fee money was charged either way); every other money sum uses `is_valid` rows.
- D26: `f_zone` flags zone 264 ("Unknown") and NULL zones only; zone 265 ("Outside of NYC") is a valid place. City-wide metrics include its trips; zone pages still cover 1–263.
- D24: in `agg_zone_hour`, `wav_match` counts trips with `wav_request AND wav_match` and `shared_match` counts `shared_request AND shared_match`, so a match is always a matched *request*. Clean trips keep the raw flags.
- D25: clean trips carry `vendor_id` (SMALLINT; the cab files' `VendorID`, NULL for HVFHV), the last unified column, after `street_hail`. `agg_vendor_month` (month × mode × vendor_id: `rows`, all rows) feeds the tie-out, which subtracts the vendors in `tie_out_exclude_vendors` (`config/sources.yaml`) before comparing with TLC. Metrics keep every vendor.
- Clean partition files at `data/clean/mode={mode}/month={YYYY-MM}/part-0.parquet` keep every column, including `mode` and `month` (DATE). The folder names are layout only: read with `hive_partitioning = false`.

## 7. Field notes

Fields whose meaning isn't obvious from the name:

| File · field | Meaning |
|---|---|
| `zones/{zone}.json` · `hour_heatmap[].trips` | average trips per week in that hour-of-week slot, over the latest 3 months |
| `zones/{zone}.json` · `top_destinations[].trips` | valid trips in the latest month, all modes, from OD pairs with ≥ 20 trips; `share` is of the zone's valid trips |
| `zones/index.json` · `share_change_yoy` | change in ride-hail share vs a year earlier (fraction points); `yellow_share_change_yoy` likewise for yellow |
| `companies/{mode}.json` · `lyft_vs_uber` | per zone: `gap` = Lyft share − Uber share of all trips in the zone; `gap_change` vs a year earlier. `null` on cab pages |
| `companies/{mode}.json` · `compare[]` | one row per metric, a value per company; `unit` as in `site/tiles.yaml` plus `usd_per_minute` |
| `congestion.json` · `effects[]` | `cp_effect_summary` rows: median and p10–p90 of weekly effects, both zone lists |
| `congestion.json` · `zone_change[].change` | pickups per day in 2025 vs 2024, all modes (`cp_zone_change`) |
| `drivers.json` · `tlc_as_of_month` | latest month in the TLC indicators file; the TLC-reported tiles use it |
| `drivers.json` · `event_study[]` | `week_offset` 0 is 2025-W31 (`transition: true`); `year` 2024 rows are the seasonal reference |
| `airports.json` · `fares[]` | trips from the airport to Manhattan: `fare_mean` = rider total ex tip per trip, `fare_base_mean` = base fare per trip |
| `prices.json` · `fpm_by_hour[]` | ratio-of-sums fare per mile and per minute by hour of week, latest 3 months |
| `taxi_zones.geojson` | FeatureCollection in WGS84, properties `LocationID`, `zone`, `borough`; exterior rings clockwise as d3-geo expects. mapshaper 0.7.98 writes RFC 7946 (counter-clockwise) rings by default, so `pipeline/zones.py` passes `gj2008` to get clockwise ones. The mock is a grid, not real zones |
